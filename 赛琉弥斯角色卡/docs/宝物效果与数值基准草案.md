# 宝物效果与数值基准草案

现行实现：用户已授权确定天赋数值并实施成长、常规装备与修为秘宝，见[天赋成长与常规宝物 V1](天赋成长与常规宝物V1.md)。下文为此前设计背景；属性百分比 K、成长速度和已实现范围以 V1 为准。条件伤害仍待战斗事件接入，特殊机制待用户确认，投放继续暂停。

状态：五类分类、效果方向、按宝物品级限制绝对增益、静默丢弃、容量提醒及获取分工已由用户确认；本文件的槽位、品阶换算、系数、具体上限与特殊机制示例仍为待评审提案，尚未写入实际聊天或运行脚本。概率投放方式须另行研究并由用户确认。依据为[人物培养与宝物管理需求](人物培养与宝物管理需求.md)及现有 N2 人类模板，不宣称完整战斗、经济或成长平衡已验证。

## 分类与用途

| 分类 | 主要用途 |
| --- | --- |
| 武器 | 攻击与作战能力 |
| 防具 | 防御与生存 |
| 饰品 | 辅助属性、条件增益或其他已定义效果 |
| 修为秘宝 | 直接补充修为，或佩戴期间提高成长速度 |
| 特殊物品 | 具有独立触发机制与限制的特殊能力 |

每件宝物只有一个主分类，另记使用方式与效果。修为秘宝允许“使用后消耗”和“佩戴持续”两种方式；其他装备可有成长副效果，但不因此复制一件宝物或重复生效。特殊物品须按机制分类，单纯增加更大数值不作为特殊性的依据。普通疗伤、回能药剂继续沿现有库存和药剂规则管理；删除宝物的材料分类不清除领地材料。

## 品阶与配装基准（提案）

- 首版数值按八档品阶校准，`J=1..8`、`Qj=1,2,4,8,16,32,64,128`。这些是数值档位，不新增正式世界内品级名称。
- 人物达到对应路线的品阶要求才可激活宝物；超阶所得可保留在库中。装备的适用路线、对象与体型写在规格里，不把人类装备的固定值自动按巨龙体型放大。
- 首版六个生效位置：武器一件、防具一件、饰品两件、佩戴型修为秘宝一件、特殊物品一件。消耗型秘宝不占佩戴位置。收纳、预览或仅拥有不触发被动效果。
- 同件宝物只归一个人物，不能重复占位；整个人物的生效装备共同计算上限，换槽位和跨分类不能绕过。
- 每件常规宝物的总词条预算为一份完整主效果，或两份各半强度效果，不能把下表全部效果同时满额装入一件物品。特殊机制另按触发频率、强度与代价校准。

## 常规主效果（提案）

同一品阶的一份完整主效果：

| 效果 | 固定基准／上限 |
| --- | --- |
| 生命上限 | `+20Qj²` |
| 指定路线能量上限 | `+20Qj` |
| 无资源普通攻击 | `+Qj²` |
| 有效防御 | `+0.5Qj²` |
| 单一属性百分比、通用伤害增幅或成长速度 | 基础百分比 `min(5%×J, 20%)`；三者是不同效果，分别择一 |
| 对一种已登记系别的伤害增幅 | `min(5%×J, 20%)`，只在目标标签匹配时触发 |
| 消耗型修为秘宝 | 向指定已有路线增加固定 `10JQj` 修为，成功结算后数量减一 |

固定数值取宝物品阶，在获得时确定；不随佩戴者晋阶自动重算成更高品阶。百分比效果使用“按基础值计算，但最多增加宝物品级允许的固定数值”的规则，不再采用人物境界比值衰减。小数使用一致精度保存，防御等合法小数不能逐件向上取整。

对属性 x 的单条百分比效果：`实际增益 = min(基础属性 Bx × 词条百分比 p, 该品级该效果的绝对上限 K[j,x])`。每个上限按宝物品级及效果规格确定，不随当前佩戴者的属性上涨。仅作机制示例：一条“攻击 +10%，最多 +5”的效果，在基础攻击 20、100、1000 时分别增加 2、5、5；此处 10% 和 5 不是已定物品。

具体 K 表待校准。属性类可评审以同阶已定义模板的对应属性乘词条百分比作为基准，但不得把此候选公式视为已通过。伤害类上限使用每次原动作预算的伤害点数，成长类上限使用每单位剧情时间的额外修为点数，不能把百分比上限误当绝对数值上限。缺少模板、效果规格或天赋速率时保持待配置，不按当前高阶人物临时放大上限。两条半预算效果的上限也按预算分配，不各自占满一件宝物的额度。

## 合成与总上限（提案）

### 面板

设不含宝物的基础属性为 B、对应固定增益总和为 F；对每条百分比效果分别按其品级上限截断后，求和得到 A：

`A = Σ min(B×p_i, K_i)`

`有效属性 = B + min(F + A, B×50%)`

生命上限、各路线能量上限、有效防御、无资源普通攻击分别使用此式，最多提高到基础的 150%。百分比只按基础 B 计算，不再次乘放大后的属性，也不乘其他宝物。基础防御已包含通常防护，只加入宝物的额外防御，不能重复加入普通军甲。

若某项基础值确为零，百分比部分仍为零；合法固定增益的额度改以已确定的同阶对应模板值为参考，避免零基础导致装备永远无效。没有对应模板时列为待定，不临时编造参考值。普通攻击总增幅的零基础情况同样使用该已确定参考值设置额度。

面板保存基础值与宝物修正的来源，不能把修正后数值再作为下次计算的基础。能量上限变化时 C 仍等于对应上限的 20%。装备改变上限时不自动恢复当前生命或能量；卸下后超出新上限的部分按上限约束处理。真正晋阶仍沿既有规则按当时比例映射一次，两种操作不能重复映射或制造恢复。

### 条件伤害

- 通用伤害与对系伤害分别先计算 `min(原始伤害×该词条百分比, 该品级词条的绝对伤害上限)`，再按伤害点数相加，不逐层相乘。多个目标系别同时匹配时，对系部分只取截断后最高一项；通用与对系合计仍建议最多增加原始伤害的 50%。单件低阶宝物不会因佩戴者使用更高伤害技能而无限增加贡献。
- 普通攻击已有面板增益时，不把有效攻击再整体乘一次百分比。使用未加宝物的基础攻击分别合入面板修正与伤害词条，最终相对基础普通攻击总增幅封顶 80%。
- 技能读取固定版本的原始伤害，再应用专用伤害词条；提高无资源普通攻击不会自动改写所有技能。技能伤害总增幅封顶 50%，随后仍按既定先盾、再防御、再生命的顺序结算。
- 群体或多段效果在原动作预算内分配修正及绝对额度，不因拆成多段、多次结算或增加目标数重复领取一份主效果、重置品级上限。状态查看与界面刷新不触发效果。
- 目标系别必须来自明确档案；缺失时不按姓名、技能名或装饰描述猜测。无目标的面板展示通用值，选中已知目标后可展示对应条件值。

### 成长与修为秘宝

- 佩戴加速效果作用于已确定的天赋基础速度 v；每条额外速度为 `min(v×p_i, K_i)`，其中 K_i 是该品级效果每单位剧情时间最多提供的额外修为。各件额外速度相加后，总额外加速建议最多为 v 的 50%。低阶宝物对高速度人物仍只提供自身有限的修为／时间额度。天赋基础速度或对应品级上限未定义时保留待配置状态，不按零速度或任意默认天赋结算。
- 装备、卸下、换人或晋阶先按旧配置结清此前剧情时段，再从该时点使用新速度；不让新宝物追溯放大旧进度。
- 消耗型秘宝每次增加物品中登记的固定修为。同一路线每剧情日的额外吸收上限建议为当日首次使用前晋阶门槛的 20%；在首次使用时锁定该日额度，晋阶、换物品或重新打开界面不刷新。宝物品阶仍须满足使用条件。
- 额度不足以完整接收一件时不消耗该件，不先删除库存再丢弃效果。成功时消耗与修为增加作为同一笔事务，达到门槛自动晋阶并保留溢出；R8 不凭空新增下一阶。
- 同阶一件秘宝等于对应晋阶门槛的 10%，每日最多完整使用两件。此数值仅控制局部速度，整体晋升耗时还须与天赋速度、获得频率和获取成本共同校准，不能据此宣称整体成长节奏已平衡。

## 特殊物品机制示例（未确认）

| 候选机制 | 可以体现的特殊性 | 必须写清的限制 |
| --- | --- | --- |
| 护命契印 | 一次符合条件的致命伤害后保留一点生命 | 适用境界、一次充能、何时扣充能及恢复方式；不倒转已经发生的死亡 |
| 蓄能镜 | 储存一次符合条件攻击的一部分伤害，之后主动释放 | 储存上限、有效攻击类型、释放次数、到期时点；不递归触发镜面效果 |

以上仅说明机制方向，不是自动赠送的三件宝物。每种特殊物品必须有受支持的效果处理器和固定规格，不能用“其他效果”作为任意执行脚本或无限追加能力的入口。未接入地图等模块的特殊能力，先定义边界再实现，不因有特殊分类就默认支持传送或时间回溯。

## 脚本与 AI 的职责

前端负责展示与操作，统一结算模块负责存档与所有宝物算术。持有、穿戴、消耗、修为、效果次数和冷却都按当前聊天有效分支接续，重生成、切分支或回退不得重复领取。

入库时只需由脚本核对宝物是否出自自己的生成记录并防止重复入库，不对 AI 增加严格机会回执或复杂审核。AI 负责演绎及判定获取是否成功，脚本负责按对应品级与效果库生成属性。用户或 AI 自行口述的宝物没有脚本生成记录，不能直接转为有效库存。获取门槛需预先告知 AI；门槛内容、投放剧情的方式、生成频率与条件、生成与反馈的具体时序均列入 INT-14 待研究，不在 UI 阶段擅定。

界面允许丢弃装备，脚本清理当前有效物件、佩戴关系与加成；不调用 AI 或发送丢弃事实。容量接近上限时只在界面提示清理，不自动替用户丢弃。容量与预警阈值仍待确定；废弃物件不转存为无限增长的完整档案，必要防重信息须有界且能阻止旧获取结果再次发放。完整要求见[需求文件](人物培养与宝物管理需求.md)。

主 AI 需要的是当前相关人物的有效面板、可采取的宝物能力，以及已经发生的增益／触发／晋升事实，不接收完整算法或全部离场人物账本。命中、目标和行动等剧情事实须有明确来源；单次模型回复中新出现的敌人或动作不能被生成前脚本预知，接入时须设计可用的事件契约，不能把事后改数值冒充事前已结算。

是否将最终面板及宝物触发事实并入现有通用剧情汇总器，在实施计算脚本时按根约定由用户确定；丢弃通知已明确排除。本草案不注册提供器、不部署运行脚本、不新增模型请求。

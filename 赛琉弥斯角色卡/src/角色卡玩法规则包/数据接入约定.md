# 后续数据接入约定

独立 schema 已按下表职责实现，统一位于 stat_data.玩法；空初值不初始化人物和资产余额。这里的路径是独立包约定，尚未映射到任何现有角色卡。接入前须核对目标卡的现有 schema、MVU 版本、初始化和输出格式、变量列表及其他脚本对同一事实的所有权。

| 内容 | 最少记录 | 唯一性与更新边界 |
| --- | --- | --- |
| 人物 | 玩家和确需连续独立结算的关键人物：已算好的境界品质、上限、防御、无资源攻击、各已有路线 C、已掌握技能版本；当前生命及各路线能量 | 同一人物只有一份余额，军队和领地按身份引用。不因取名、高境界或最强而自动建档；首次登记接续已有伤势消耗。 |
| 技能 | 版本标识、路线与掌握条件、固定消耗效果、范围、行动准备及必要结束条件 | 定义与人物掌握分开。持有定义不等于掌握，晋阶不自动升级旧版。候选和实验性状态应随定义保留。 |
| 生效状态 | 实际存在的个人盾剩余值与结束交锋、准备技能与剩余准备、必要效果强度与结束交锋 | 不预填不存在的空效果；耗尽、释放、中断、替换和到期按事件清理，不依赖回复条数。 |
| 药剂 | 固定物品规格、实际库存、人物共享的下次可生效时间 | 同一库存不另建一份药剂余额；提前服用扣库存但不恢复。 |
| 军队 | 所属、职业境界构成、存活人数、其中伤员、必要死伤结果与命令 | 受伤者属于存活人数，转死／恢复只改实际变化；不逐兵建生命、伤害池或培养账。 |
| 经营 | 资金、补给、材料唯一库存；领地等级、合同日率、实际建设与招募 | 同人不重复计费，物资转移一增一减。既有库存映射后再补缺字段，不凭空新建初始资源。 |
| 成长 | 已登记人物的天赋成长进度、已有路线与已结算时点；技能学习单独记录 | 后台按剧情时间积累、达标自动晋阶，离场不停；天赋速率待配置，AI 不重复结算。晋阶保持原有生命与能量比例，不逐兵建档。 |
| 时间 | 当前有效分支的剧情时间、实际交锋序号和有关事件起止／已结算节点 | 复用已有时间事实，不另外维护并行时钟；不建每分钟恢复日志或地形预算余额。 |

运行状态采用当前聊天有效回复分支的消息楼层 MVU 数据；不要将事实余额放进全局、角色或脚本变量。重生成从该回复之前的有效状态开始，切换 swipe 后读取对应分支状态，不能在被替换回复的结果上再扣费。仅重复读取、刷新、切换界面不得触发恢复或经营结算。

AI 一次回复完成正文和必要增量更新，程序只存取、校验和后续展示。校验不自动重算战斗、不在正文后重新裁判、不追加第二次模型请求。若既有卡中已经有地图时间、经营库存等字段，先明确其映射和写入职责；本包不自动接入这些项目。

只有后续确实新增计算剧情事实的脚本时，才按 `docs/剧情信息汇总器.md` 另行确定是否注册相应事实；本包没有注册任何内容。

## 整卡时间对接

- 地图时钟接管后，整卡以其为唯一权威时间；`stat_data.玩法.时间.剧情时间` 仅由脚本同步为当前有效分支的时间副本，AI 不得另行写入或累加。
- 地图叙事模式继续由 AI 提交本轮耗时报告，脚本统一结算后同步；地图实时模式仅使用脚本已经提交的时间。
- 明确未启用地图时钟的独立玩法仍沿用原时间规则。时钟故障、同步缺失或待核对不视为解除接管，不自动让 AI 重新掌握时间写入权。
- 休整、药剂、学习、修炼和工程均按同一权威时间接续；实际交锋编号仍由已发生的交锋决定，不用现实时间或回复次数代替。

注册入口已安装地图时间同步：生成前读取有效父分支，回复结算和分支切换后读取所选分支；只修改已有 MVU 记录的剧情时间，不启动第二个时钟、不改地图存档、不结算恢复或经营。MVU 更新结束时在 schema 校验之前恢复地图权威时间，地图数据暂不可用时保留之前的时间；已有地图存档时，时钟运行故障不会恢复 AI 的时间写入权。具体跨模块范围见 [功能与世界书对接待办](../../docs/功能与世界书对接待办.md)。这不代表休整、药剂与工程联动已全部完成。

## 独立结构的实际路径

- `玩法.人物[人物ID]`：生命、攻防、已有路线的境界品质与能量、修炼进度、已掌握版本、共用药剂时间。`玩家人物ID`只是引用。
- `玩法.技能定义[版本ID]`：名称、确认状态、路线、门槛、固定启动费用和完整规格。文字规格承载不同技能的范围、准备、伤害池等差异，避免为每人复制技能表。
- `玩法.护盾／准备／实验性地缚／休整[人物ID]`：只保存存在的记录，删除字典中的人物键即清除状态，解析不把它补回。
- `玩法.当日修炼[人物ID]`：旧训练账的兼容字段，保留历史，不再新建或更新；每日四点不作为新天赋成长上限。后台结算的天赋配置、游标及提示接口尚待实现，详见[人物培养与宝物管理需求](../../docs/人物培养与宝物管理需求.md)。
- `玩法.库存[库存ID]`：唯一资金、补给、材料和物品数量。物品规格写明药剂固定恢复量与路线；基本补给和材料不在物品栏重复登记。
- `玩法.军队／领地／合同／项目`：各自稳定 ID 和库存引用；军队含职业境界分组，领地产出和合同支出各有实际结算至时点，不另存可漂移的净余额。
- `玩法.时间`：剧情时间和从初始化起累计的已结束交锋编号。施放发生在第 t 个交锋时，三交锋个人盾结束于 t+2，地缚结束于 t+1；AI 依据实际交锋清除，schema 不自动清理。

空初始化中的 null 日期不是现实时间，也不是自由领取恢复的依据。未核清旧聊天药剂、经营或成长历史时，先完成映射核对，不能直接套用空初值。数值越界或引用缺失时校验失败并保留错误供修正，不暗中裁定一次战斗应扣多少；JSON Schema 用于字段形状提示，跨字段与引用检查以 Zod schema 为准。

## 装备与宝物接入

人物的可选 `装备` 字段用槽位映射 `{库存ID, 物品ID}`。库存物品的可选 `宝物` 元数据记录大类、子类、适用路线、使用方式和归属人物 ID；法杖必须登记为武器／法力。旧存档无需补空装备字段。

界面调用角色脚本的当前分支接口，佩戴叠放物件时拆出单件，同一件不被多个人物或槽位重复占用；丢弃最后一件清理引用，不写废弃日志，不向 AI 发通知。实际效果库与最终攻防合成仍待接入，不能把可选固定加成字段视为定稿系数。

`玩法正文` 是脚本重建的只读镜像，不作第二套余额来源。世界书变量列表只读该镜像，人物装备转换成当前武器名称，脚本宝物记录不发送 AI。所有 JSON Patch 仍针对 `/玩法/...` 的普通剧情字段，脚本保护装备和宝物记录。变量结构脚本和两条相应世界书必须配套替换；当前源码交付不表示已安装到实际酒馆。通用剧情信息汇总器尚未注册装备事实。
